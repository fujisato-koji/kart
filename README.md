# A traceable record

This repository keeps the record of one physical thing, from its design through building, operation, change, and removal, under the [traceable-design](https://github.com/traceable-design/traceable-design) standard.
An AI assistant writes most of the record; the owner decides.

## Start

1. Fill in "About this project" in `AGENTS.md`.
2. Open the repository with your assistant and say what you want to make.
   The assistant follows `.claude/skills/traceable-design/SKILL.md` and starts by asking the questions that can rule a form out.
3. Keep private facts, such as where the thing stands, outside this repository.
   To have CI refuse them, put one name per line in a repository secret named `TDR_PRIVATE_NAMES`.

## Layout

| Path | Content |
|------|---------|
| `record/` | The facts: requirements, values, sources, decisions, open items, hazards, parts, interfaces, checks, shared items, baselines, runs, procedures. |
| `docs/` | The reasoning, one file per step, citing facts by id. |
| `STATUS.md` | The current state, generated by `python tools/tdr.py status`. Read it first; never edit it. |
| `tools/tdr.py` | Checks, status, lookup, briefs, and an MCP server. Python standard library only. |
| `calc/` | The calculations of steps 1.2 and 1.3. `calc/design.py` writes the design's values and geometry; it solves the frame with `calc/frame.py` and searches for interferences with `calc/clash.py`, which need numpy and scipy (`pip install -r requirements-calc.txt`). |
| `.claude/skills/traceable-design/` | The instructions the assistant follows. |
| `.mcp.json` | Registers the `tdr` MCP server for assistants that read this file. |

## Commands

```bash
python tools/tdr.py status            # write STATUS.md
python tools/tdr.py check             # refuse anything that breaks the rules
python tools/tdr.py check --gate design_build
python tools/tdr.py get R-01          # one item and its basis
python tools/tdr.py refs bracket      # what refers to it
python tools/tdr.py brief bracket R-02
python tools/tdr.py tier --message change.txt
python tools/tdr.py mcp               # MCP server over stdio
```

## Site

The record is published as a MkDocs Material site at https://fujisato-koji.github.io/kart/ by `.github/workflows/pages.yml`. It holds the reasoning pages in `docs/`, a navigator over the record (`docs/navigator/`) and a 3D simulator (`docs/viewer/`). In the pages, value keys get badges and item ids link to the navigator.

```bash
pip install -r requirements-site.txt
python tools/gen_site_data.py   # regenerate docs/data/record.json from record/
python tools/ja.py todo         # list record prose that has no Japanese for the navigator yet
mkdocs serve                    # preview at http://127.0.0.1:8000/kart/
mkdocs build --strict
```

`docs/data/record.json` is generated from `record/`; do not edit it by hand (`python tools/gen_site_data.py --check` fails if it is stale). The navigator is Japanese (D-034): `docs/data/ja.json` maps each English prose string to its Japanese, `python tools/ja.py add <file.json>` merges new translations, and `python tools/ja.py check` fails while any string lacks one or a translation drops a value key or id.
